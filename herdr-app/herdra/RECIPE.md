# Herdra

A **Herdra** button in the tab row and a floating window on the right of Herdr: Algorant's tracker (task-57, mockup Sideshow post V1m9t4not0Y, sources `research/task-57-mock/`). It lists what Herdra's reply footer lists, from the same source (`bin/herdra-open`), and a click on any item shows its context and the decision asked. Nothing is stored beyond a snapshot in Herdr's shared state: each poll reads the existing CLIs again.

## What you see

- **The button**, in `main-sideshow`'s tab row: a 100px block left of Usage (when installed) and Sideshow. It is a 26px pill with an inbox icon and "Herdra", 12px `muted` text on `chrome`. When something needs Algorant it reads "Herdra · N", with N semibold in `working` (amber). With nothing waiting it reads just "Herdra". It is filled `selected` while the window is open.
- **The window** sits where the Sideshow window does (task-47): top on the pane cards' top line (tab row height + work padding), bottom above the status bar, 8px in from the right edge, and 45% of the window wide. It is frameless, on theme `background` with a 1px `border` and radius 10, and is remembered (`key: "herdra"`, `keep: true`).
  1. **Header**, 42px: a 7px dot (`working` when something needs you, `blocked` on a read error, else `accent`), "Herdra" in 11px `dim`, then a summary such as "3 need you · 1 in progress · 5 up next · laptop offline". On the right are **Herdra →** and **✕**.
  2. **Fleet strip** (extra A): one line, each Ceph's status dot (`working` amber, `blocked` red, else `dim`) and project name, Herdra included, then any machine that is offline.
  3. **Body**, scrolling, padding 12×14, 16px between sections; each has a 12.5px semibold title, a count pill and a one-line `dim` note, then one `chrome` card of rows (a 20px project chip, the headline, a `dim` meta line, a status on the right and a `›`). Every section is `herdra-open` items only, in this order:
     - **Needs you**: items `on: algorant`, lowest `--rank` first. Meta: project, the linked Task, "Herdra: <the recommended option>", raised when. Right: the kind (Decide, Approve, Check, Read). Count pill in `working` when non-empty.
     - **In progress**: items `on` an agent. Right: that agent's status and, while working, how long; an agent idle or done while it still owes the item (herdra-open's `silent`, the same rule and mark as the footer) shows "idle" and how long it has been, e.g. "idle 58m" — always "idle", never hc's own "done", which beside the pill would read as time since completion.
     - **Up next**: items `on: herdra` or parked, numbered by rank; a parked decision owed by Algorant carries "yours".
     - **Done**: items closed in the last 24 hours, newest first, ✓ and when; the close note is the headline.
  4. **"On boards, not raised" bar** (extra B), fixed at the bottom: validation and delivered Tasks on the Ceph boards that no open item links to, with a count, a preview and **Show ›**, which lists them (a click loads and expands the summary, a `tandem show` on that project's Ceph, and then shows **Post ↗**; **Conversation →** while it is closed).
- **A click on a row** replaces the list with the item's detail view: **‹ All**, the project and Task, the kind; then the title, a meta line (section, raised when, waiting, closes), **What's asked** (`--ask`), **Options** (lettered; the one `--rec` starts with is marked "Herdra recommends"; no buttons, the window writes nothing), **Herdra's recommendation**, **Links** and **History** (the item's log lines, newest first). A Done item shows its **Outcome** instead of options. The bar says which `herdra-open` entry it is. The detail follows the snapshot, so it refreshes in place; an item that has left Done shows "no longer in Herdra's list".
- **Links**: **Task** shows its project board's state when the board read knows it, **Summary ›** expands its record (a `tandem show` on that project's Ceph, once) and **Post ↗** appears when it holds a Sideshow link; **Post** opens in the Sideshow window; **Agent** shows its live status and **Conversation →** runs `pane.focus {terminal}` when Herdr shows it in a pane, else `terminal.peek`; **Thread** expands the inbox conversation.
- An empty section shows a one-line card ("Nothing needs you.", …).

## How it behaves

- **One source.** `herdra-open footer` (Herdra's reply footer, pasted as is) and the window both read `herdra-open`; `list --json --closed 24h` gives the window open items and the last day's closed ones, each with its `section` and its `history`. `section` is computed there: `--pending` is Pending, parked or `on: herdra` is Up next, `on: algorant` is Needs you, any other `on` is In progress, closed is Done. An In progress item whose agent is SILENT (idle or done for 15 minutes while it still owes the item and nothing works under it, `bin/lib/silent.ts`, the one rule `herdra-checkin` judges an agent with) carries `silent: {status, at, age, mark}`: `mark` is the footer's " (idle 58m)" (`status` keeps hc's own word, `at` the status start for the window's line). Pending also lists, after its items, the Tasks tagged `needs-<host>` on the project boards, from `herdra-online --list --json` (read with the boards), as the footer does.
- **hc and the boards only decorate.** An item's agent is its `agent=` link, else the live terminal named like `on` (after an `@`, on that machine), else the Ceph of the space it names ("obsmd Ceph"); it gives the status pill and time. A linked Task found on a board gives its state. Neither adds an item. Blocked agents and validation Tasks with no entry are not listed; a blocked agent shows in the fleet strip, an unlinked Task in the bottom bar.
- **Instant open.** The window draws on its first frame from the snapshot in shared `"herdra.snapshot"` and refreshes in place. The button, always running, keeps the snapshot current, so there is nothing to wait for; with no snapshot yet (a fresh `shared.json`, or one written by another `shape` of this mod, which is ignored) it draws "Reading…" for the first poll. The snapshot has two parts, each written only when it changed (setShared redraws every mod): `fast` and `board`.
  - `fast`, every 5s, one parallel read (~60 ms, plus ~20 ms: `herdra-open list --json` runs `bin/herdra-silent` inside it, one `hc ls` and one `hc get` per idle or done owner, to mark a silent one): `hc ls --json`, `hc machine ls --json`, `herdra-open list --json --closed 24h`.
  - `board`, every minute in its own task, off the open path and parallel across every running Ceph's board (the agent in a space's `main` tab, local or through `exec(…, {on})`): one `tandem list --no-sync --json` per board, filtered here for its delivered Tasks and its Tasks in state validation, so a refresh is one process per board and syncs no board (no fetch, push or ref work; only tandem's local `git rev-parse` to find the workspace); and `herdra-online --list --json` on workstation for Pending's machine-gated Tasks (with the boards on open and when a machine comes back, not on every refresh).
    - `--no-sync` reads the board's local files: a board another client has not refreshed yet reads as that client left it (each board's owner syncs it when it writes). A machine whose tandem predates 0.17.6 does not know the flag, so its boards are not listed at all until its tandem updates (laptop until its next reconnect, tandem task-105): there is no second read shape for it.
    - A validation row's summary, parent and Sideshow link are not in the board read: they come from `tandem show` when the row is expanded (`taskText`, once, as a task link's **Summary ›** does).
- **Machine came back (task-94).** Each fast read compares `hc machine ls` with the connected set kept in shared `"herdra.machines"` (persisted, so an app restart is not an edge; the first copy to see a change records it, so one copy acts). On workstation only, a machine that turns connected runs `hc run --rm --no-parent bin/herdra-online <machine>` once, which tells each owner its Tasks tagged `needs-<machine>`; a failed run posts an error notice (details in `~/.local/state/herdra/online.log`).
  - The open window runs the same two loops, so it also works when no button is in the layout; one run of each at a time.
- **Working time** counts from when a poll first saw the agent working (`hc ls` has no start time; it is kept as `since` in `fast`, so it restarts when an agent turns idle and works again).
- **Open-to-first-draw** is recorded: the click stamps `props.openAt`; the window's first render writes `{ms, snapshot, board}` to shared `"herdra.openMs"` (and `console.log`s it). Read it from `~/.config/herdr-app/shared.json`.
- **Toggle:** the button, `ctrl-shift-h`, or `herdr-app do mod.open:herdra` (a 2×2 frameless popup that toggles the window and closes itself): press to open, press again to close, as `ctrl-shift-s` does for Sideshow. The open window's overlay id is in shared `"herdra.window"`.
- **Key:** `keys.json` here holds the snippet to merge into `~/.config/herdr-app/keys.json`: `"global": { "ctrl-shift-h": "mod.open:herdra" }`. `ctrl-shift-h` was free (checked against the live `keys.json`, task-74). Herdr's Help overlay (`ctrl-shift-?`) lists it as "mod open herdra".

## Built from

- `mods/herdra/mod.json`: `{"place":"none","title":"Herdra","overlay":{"kind":"popup","frame":"none","width":2,"height":2}}`.
- `mods/herdra/main.js`: one `View` with three roles (`props.button`, the `mod.open` toggle popup, `props.window`); `keepCurrent` runs the two loops; the window is the list or, with `this.sel`, one item's detail.
- `mods/herdra/data.js`: reads (`readFast`, `readBoard`), pure builders (`buildFast`, `buildBoard`), the snapshot (`snapshot`, `refreshFast`, `refreshBoard`) and the on-demand `threadText` and `taskText`.
- `bin/herdra-open`: the source (its header lists the fields). `bin/herdra-silent` adds the `silent` mark to a list on stdin, from `bin/lib/silent.ts`, the SILENT rule `bin/herdra-checkin` shares.
- The tab row comes from `herdr-app/sideshow/layout/apply.py`.

## Watch out

- **Runs programs and reads Algorant's state:** `hc`, `herdra-open` and `herdra-online` (the repo's `bin/`, found under the home folder's `Projects/herdra`), `whois` (every agent name, one batched call per read), the inbox CLI (a thread link only) and `tandem`, including on other machines through `exec --on`. It writes only its snapshot and `"herdra.machines"`; on workstation a reconnect runs `herdra-online`, which sends inbox messages.
- Open window opens must happen synchronously in the click (as in Sideshow); a window opened after an `await` never shows.
- `herdr-app check` has no async work, but it reads the live `shared.json`. Check the full render path with a throwaway copy whose `snap()` returns `{ fast: buildFast(RAW, {}), board: buildBoard({ boards: BOARDS, gated: GATED }) }` from captured JSON (`hc ls --json`, `hc machine ls --json`, `herdra-open list --json --closed 24h` from a temporary `XDG_STATE_HOME`, `herdra-online --list --json`), and run it with `check --print-spec`; delete it afterwards. Set `this.sel` (an item id), `this.open`, `this.loaded` and `this.more.board` in its `init` to render the detail, expanded links and the open bar.
- The spot is computed when the window opens; resize the Herdr window, then reopen to refit.

## Done when

- `herdr-app check ~/.config/herdr-app/mods/herdra` passes.
- A shot shows the window with Needs you, In progress, Up next and Done matching `herdra-open footer`, the fleet strip matching `hc ls`, and the bottom bar; a second shot shows an item's detail; `shared.json`'s `herdra.openMs` shows the first render within a frame or two of the click.
- **Conversation →** brings that agent's pane forward (or peeks a sub-agent), and **Post ↗** opens the post in the Sideshow window, at that post (the address it hands over is `props().url`: see [sideshow/RECIPE.md](../sideshow/RECIPE.md)).
- `ctrl-shift-h` opens the window and a second press closes it; `ctrl-shift-?` lists it as "mod open herdra".
